# Blog enable/disable guide

The blog is disabled. Its code, content and tests remain in the repository,
but enabling it requires a deliberate implementation change and validation.

## Current controls

- The pages live in `app/_blog/`. Next.js treats this as a private folder, so
  it does not generate `/blog/` or `/blog/[slug]/` routes.
- `staticwebapp.config.json` returns 404 for `/blog` and `/blog/*` at Azure's
  edge. Keep both blocks while the blog is disabled.
- `BLOG_ENABLED = false` in `app/sitemap.ts` excludes blog URLs from the sitemap.
- The public navigation and homepage do not link to the blog.

## Before enabling

1. Update `app/_blog/[slug]/page.tsx` to use Next.js 16's asynchronous route
   parameters in both the page and `generateMetadata`. The current synchronous
   `params.slug` contract needs migration before exposing the route.
2. Make the MDX heading IDs match the links generated by
   `lib/mdx/processor.ts`. The current table of contents calculates IDs, but
   the rendered headings do not receive those IDs. Check duplicate headings,
   inline formatting and non-ASCII text as part of that work.
3. Rename `app/_blog/` to `app/blog/` and update affected test imports.
4. Set `BLOG_ENABLED = true` in `app/sitemap.ts` and remove the two Azure route
   blocks. Review links, metadata, content and navigation deliberately.
5. Run `npm run check`, `npm run test:e2e` and `npm run build`. Confirm the
   exported blog index and every published post exist in `out/blog/`, and
   that `out/sitemap.xml` contains only intended published URLs.
6. Preview the exported site with `npm run swa:start`. Verify direct post
   URLs, unknown-post 404s, MDX/code rendering, table-of-contents links and
   keyboard navigation. Design changes require Kenneth's PR review under
   [AGENTS.md](../AGENTS.md).

All deployments run through GitHub Actions. Keep the blog disabled until this
work is implemented and verified.

## Disabling again

Move the pages back into `app/_blog/`, restore both `/blog` 404 route blocks,
set `BLOG_ENABLED = false`, and remove public links to blog pages. Preserve
blog code, content, components and tests.

Run the same checks and build again. Confirm there are no exported blog pages
or blog sitemap entries, and that the Azure emulator returns 404 for `/blog`
and a nested blog URL. The build copies the routing configuration into
`out/staticwebapp.config.json`.
